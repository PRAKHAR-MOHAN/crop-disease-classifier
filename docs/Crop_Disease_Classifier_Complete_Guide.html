Chapter 1: Core Theory, Definitions & System Architecture

1.1 Project Problem Statement & Goal

Smallholder farmers and agronomists need rapid, reliable, field-ready diagnosis of plant diseases and agricultural pests from a single smartphone photograph. Traditional visual inspection requires domain expertise, while naive deep learning classifiers fail in production for three classic reasons: (1) data leakage from near-duplicate images across splits, (2) overconfident wrong predictions on blurry or non-plant images, and (3) the lab-to-field domain shift when models trained on clean laboratory photos are deployed on messy outdoor farm photos.

This system solves all three problems end-to-end: given an uploaded photo of a leaf, fruit, or pest, it returns the canonical diagnosis (Crop___Disease), Top-3 calibrated probabilities, a Grad-CAM visual attention heatmap showing which pixels drove the decision, a structured agronomic advice card, and an explicit “Unsure / Not a Plant” rejection whenever confidence is low or the input is Out-of-Distribution (OOD).

1.2 Foundational Definitions

Supervised Deep Learning (Multi-Class Image Classification): Learning a parametric mapping fθ: ℝ3×H×W → ℝK from labeled RGB images (xi, yi) where yi ∈ {0, …, K−1} represents a standardized crop disease, healthy state, or pest class, by minimizing a differentiable loss function using gradient descent.
Transfer Learning & Two-Stage Fine-Tuning: Reusing convolutional/transformer feature extractors pretrained on ImageNet-1k/21k (which already encode edges, textures, veins, and shapes) and adapting them to agricultural pathology in two stages: Stage 1 freezes the backbone and warms up the random linear head so large random head gradients do not corrupt pretrained filters; Stage 2 unfreezes the full network with discriminative learning rates (smaller LR on backbone, larger LR on head).
Data Leakage & Perceptual Hashing (pHash): Data leakage occurs when visually identical or augmented versions of the same leaf appear in both training and test sets, artificially inflating accuracy. Unlike cryptographic SHA-256 (which changes if a single pixel or JPEG compression changes), pHash transforms the image via Discrete Cosine Transform (DCT) into a 64-bit structural fingerprint. Near-duplicates have small Hamming distance and are clustered into one atomic group before splitting.
Lab-to-Field Generalization Gap: The empirical drop in accuracy and macro-F1 when a model trained on controlled studio images (e.g., PlantVillage uniform backgrounds) is evaluated on uncontrolled outdoor smartphone photos (PlantDoc with shadows, soil, overlapping leaves, and glare).
Probability Calibration & Expected Calibration Error (ECE): Modern neural networks are often overconfident (predicting 99% confidence even when wrong 15% of the time). A model is calibrated when a predicted probability of p truly corresponds to p empirical accuracy. Temperature Scaling rescales logits by scalar T post-hoc without changing top-1 accuracy, drastically lowering ECE.
Out-of-Distribution (OOD) Detection: Identifying inputs that do not belong to any training class (e.g., a selfie, tractor, wall, or unknown plant). We combine three orthogonal guards: (a) a binary PlantGate CNN, (b) the Helmholtz Energy Score over logits, and (c) calibrated max-softmax probability thresholding.
Grad-CAM (Gradient-weighted Class Activation Mapping): An Explainable AI (XAI) technique that highlights spatial regions in the input image contributing most to the predicted class score. In our production ONNX graph, we prove algebraic equivalence for GAP+Linear heads and compute Grad-CAM directly via a 1×1 Convolution in <0.1 ms on CPU without shipping PyTorch.
ONNX Runtime (Open Neural Network Exchange): A cross-platform, hardware-accelerated C++ inference engine that executes the exported static computational graph (model.onnx) on CPU in ~35–90 ms per image without requiring the heavy PyTorch training library in production containers.

2.2 Data Cleaning & Quality Filtering Pipeline (ml/data/clean_and_merge.py)

  1. Integrity Verification: Every candidate file is opened with PIL.Image.verify() and re-decoded via ImageOps.exif_transpose(img).convert("RGB") so rotated smartphone photos are upright before any tensor conversion.
  2. Resolution & Aspect Guard: Images smaller than min_resolution = 64 px or with extreme aspect ratios (max(w/h, h/w) > 6.0) are rejected.
  3. Exact Byte Deduplication: A SHA-256 hash of raw bytes removes identical files. When identical hashes exist across domains, real-field records are kept preferentially (domain_priority = {"field": 0, "lab": 1}).
  4. Optional Materialization (--materialize): Writes clean, EXIF-corrected RGB JPEGs capped at max dimension 512 px to data/processed/images/, dramatically speeding up Colab/Kaggle epoch I/O.

2.3 Leak-Free Stratified Splitting Strategy (70% Train / 15% Val / 15% Test)

PlantVillage contains augmented/rotated derivatives and burst shots of the exact same leaf. A standard random train_test_split leaks near-identical leaves into validation and test sets. Our pipeline prevents this rigorously:

  1. 64-bit Perceptual Hashing: Each clean image receives a 64-bit imagehash.phash stored as a 16-character hex string (preventing signed int64 Parquet overflow).
  2. Vectorized Hamming Clustering: Using a precomputed 256-entry popcount lookup table _POPCOUNT_LUT over XORed uint64 blocks, all pairs with Hamming distance ≤ 6 are merged via a path-compressed Union-Find structure into atomic dup_group_id clusters.
  3. Stratified Group Assignment: Each dup_group_id is assigned atomically to one split (Train 70%, Val 15%, Test 15%), greedily minimizing per-class deficit relative to target ratios.
  4. PlantDoc Holdout Isolation: When plantdoc_eval_only: true, PlantDoc is held out into test_field.parquet and any PlantDoc image clustering with training pHashes is removed, guaranteeing a pure zero-leakage lab-to-field benchmark.
  5. Automated Leakage Audit: Saved in split_audit.json confirming sha256_overlaps == 0, dup_group_overlaps == 0, and cross_split_phash_hits == 0.

2.4 Handling Class Imbalance

Crop datasets are heavily skewed (e.g., Soybean healthy >5,000 images vs. minor diseases ~150 images). We support two complementary mechanisms controlled by configs/base.yaml:

  • Class-Weighted Loss (Default): Computes per-class weights wc via smoothed inverse square-root frequency (or effective number of samples) clipped to [0.25, 5.0], applied inside both standard Cross-Entropy and our custom WeightedSoftTargetCrossEntropy during MixUp/CutMix.
  • WeightedRandomSampler (Optional): Controlled by use_weighted_sampler: true to oversample minority classes at batch construction time.

Chapter 3: Every Mathematical Formula Used in the Project

1. ImageNet Channel Normalization (Preprocessing & Inference)

After resizing to round(224 × 1.14) = 256 and center-cropping to 224 × 224, pixel values x ∈ [0, 255] are standardized per RGB channel:

xnorm, c = (xc / 255.0) − μcσc,    μ = [0.485, 0.456, 0.406],   σ = [0.229, 0.224, 0.225]
2. 64-Bit Perceptual Hash Hamming Distance (Near-Duplicate Detection)

Given two 64-bit unsigned integer pHashes ha, hb, bitwise XOR marks differing frequency bits and byte-wise popcount sums them:

dH(ha, hb) = ∑b=0..7 LUT[ ((ha ⊕ hb) >> 8b) & 0xFF ] ≤ τpHash = 6
3. Class Imbalance Weighting (Inverse Square-Root & Effective Number)

For total training count N and class c count Nc, raw weights are normalized by their mean w̄ and clipped to [0.25, 5.0]:

wcraw = √(N / max(Nc, 1))   or   1 − β1 − βNc (β=0.999),     wc = clip(wcraww̄, 0.25, 5.0)
4. Label Smoothing, MixUp & CutMix Soft Targets

With label smoothing ε = 0.1 over K classes, one-hot labels become smoothed vectors ysmooth. With probability p = 0.5, two samples (i, j) are blended with λ ∼ Beta(α, α):

ysmooth, k = (1 − ε) · 𝕀[k = y] + εK   |   MixUp: x̃ = λxi + (1−λ)xj,   ỹ = λyi + (1−λ)yj
CutMix: λadj = 1 − (x2 − x1)(y2 − y1)W · H,   ỹ = λadj yi + (1 − λadj) yj
5. Weighted Soft-Target Cross-Entropy Loss

Used during training with MixUp/CutMix so class weights remain active even on blended targets:

wsample, b = ∑k=1..K ỹb,k · wk,     LWCE = − ∑b=1..B wsample, b ∑k=1..K ỹb,k log(softmax(zb)k)max(∑b=1..B wsample, b, 10−8)
6. Knowledge Distillation Loss (Teacher → Lightweight Student)

Combines hard ground-truth Cross-Entropy with temperature-scaled Kullback-Leibler divergence (T = 4.0, αKD = 0.5):

LKD = (1 − αKD) LCE(zs, y) + αKD · T2 · KL( softmax(zt / T) ∥ softmax(zs / T) )
7. Step-Level Cosine Learning Rate with Linear Warmup & EMA

For step t, warmup steps Tw, total steps Ttot, and minimum ratio rmin = ηmin / ηmax:

λ(t) = { t + 1Tw if t < Tw;   rmin + 1 − rmin2 (1 + cos(π t − TwTtot − Tw)) otherwise }   |   EMA: θEMA(t) = 0.999 θEMA(t−1) + 0.001 θ(t)
8. Evaluation Metrics & Lab-to-Field Generalization Gap
Macro-F1 = 1K ∑c=1..K 2 Pc RcPc + Rc,    GapAcc = Acctest_in_domain − AccPlantDoc_field,    GapF1 = F1test_in_domain − F1PlantDoc_field
9. Post-Hoc Temperature Scaling & Expected Calibration Error (ECE)

A single positive parameter T = clip(exp(log T), 0.1, 10.0) is fitted on validation logits via L-BFGS minimizing NLL. Predictions are binned into M = 15 equal-width bins:

p̂c(x) = exp(zc / T)∑j=1..K exp(zj / T),     ECE = ∑b=1..M |Bb|N | acc(Bb) − conf(Bb) |
10. Helmholtz Free-Energy OOD Score & PlantGate Probability

Log-sum-exp is shifted by zmax for numerical stability. More negative energy = confident in-distribution; energy above threshold triggers OOD rejection:

E(x) = −(zmax + log ∑c=1..K exp(zc − zmax)) > τenergy ⇒ OOD,    P(plant) = 11 + exp(−zgate) < 0.45 ⇒ Non-Plant
11. Grad-CAM & Algebraic Equivalence to ONNX 1×1 Convolution

In standard Grad-CAM on spatial map A ∈ ℝCf×Hf×Wf, gradient weights are averaged spatially. For Global Average Pooling + Linear head (yc = bc + ∑k Wc,k (1/HfWf)∑i,j Ak,i,j), the partial derivative is constant across (i, j):

αkc = 1Hf Wf ∑i,j ∂yc∂Ak,i,j = 1Hf Wf Wc,k  ⇒  LGrad-CAMc = ReLU(∑k Wc,k Ak) = ReLU(Conv1×1(A; W))

This exact algebraic equivalence allows the exported ONNX model to emit both logits and cam_maps in a single CPU forward pass in <0.1 ms without backpropagation or PyTorch in production.

  • python-json-logger: Emits machine-parseable JSON logs stamped with per-request X-Request-ID.
